# Testing

Owns: what `swift test` covers, what it deliberately does not, and the conventions the suite depends on. Toolchain and build flags: [build-from-source.md](build-from-source.md).

```bash
swift test
```

The Sparkle feed writer is not in that suite. `python3 Scripts/appcast_test.py` checks it without a private key and without writing `appcast.xml`: a version already in the feed has its enclosure replaced, and the feed is left with that one newest item. [releasing.md](releasing.md)

There was no test target until 2026-09-07. What prompted one was not a policy: two real faults were found by reading code in a single afternoon — Antigravity taking the first matching helper and giving up when the one that answers was second, and `.stale` being treated as a failed fetch when a *successful* one produces it too — and the notification rules had shipped with nothing proving them at all.

## What is covered

Every suite is a synthetic check of production code — no live provider, no real credential, no whole-app profiling, no real pointer input. Rows name what each suite pins; the cases themselves are in the suite. Suites sharing a row share a file or a topic.

## What is not, and why

**No UI tests.** Synthesised events cannot drive the accessory `NSPanel`'s hover: `hitTest` and synthetic `NSEvent`s reported a handle reachable while real clicks were dropped ([ui/input.md](ui/input.md)).

**A rule test is not a chain test.** `AlertMemoryTests` feeds the state machine directly, and review twice missed a defect between service and machine: the cache swapped a failure for cached figures and lost the reason. Test a rule through whatever it depends on upstream.

**No network, no clock, no disk in a rule test.** That is why `AlertMemory.alerts` takes `now` and `UsageCache.init(file:)` takes a path.

**No live provider calls.** Every route needs a real credential and answers differently by plan. Fixtures are captured by hand from a real reply and committed; the provider's page records the capture.

**A second-hand fixture says so where it lives.** One written from another project's parser or a vendor's shipped client is second-hand: Volcengine's (nobody here holds that plan) and Command Code's (field names from its published npm bundle). It pins a shape against change, not that the shape is right; a captured one replaces it when someone with an account can produce one.

**The added agent readers are spec evidence, not machine evidence.** Their suites read hand-built stores in the documented shape through the production reader; no one's transcripts are committed, and no reader written from a second-hand format spec has run against the product that writes it. A reader reporting `notes` (a transcript it could not decode) is validated no further than the suite's store. Each source's evidence is marked in [token-spend-sources.md](token-spend-sources.md).

**A subprocess test really spawns one.** `VolcengineProcessTests` runs `/bin/sh` because a child that fills the stderr pipe or never exits cannot be faked and is invisible to reading: two versions of the runner looked correct and hung. The deadline is a parameter so a test can use one second.

**A kill is timed on the runner's thread, against the budget that thread spends.** Two waits sit outside that budget, and each has failed a wall clock that included it. The runner enforces its deadline on a global queue, but the caller only resumes when a cooperative thread is free. Swift Testing runs synchronous tests on that pool, and on a three-core CI runner a few long ones held it for about 19 seconds, so every test started meanwhile reported 18–19 seconds — pure parsing ones too — and children killed at three seconds were measured at twenty-two, failing `< 20` from 1.12.1 (2026-10-16) until 2026-10-18. Saturating the pool locally reproduces it: the child dies on time, the caller resumes when the pool frees. The other wait is the one for a utility-QoS thread: `run` and `fetch` queue there before the deadline starts. The extension timeout test still started its clock before that hop and allowed ten seconds; on the 1.4.28 Build the program was already dead and the call returned under a second later, but the clock read 12.9 seconds and failed. Kill cases call `runSynchronously` or `fetchSynchronously` on a thread of their own and start the clock there. The bound is the one-second deadline, plus `BoundedProcess.escalationBudget`, plus five seconds to create the process. `ProcessDeathWatch` reads the pid the script writes and reports the death instant from its own thread, so a slow resumption cannot move it, and kills a survivor after thirty seconds. The child sleeps five minutes, past the bound. Both suites fail when the kill is disabled.

**The animated mark's motion is measured, not eyeballed.** Two of its properties cannot be seen in a screenshot and are read off the frames instead: that working pumps visibly harder than idle (peak-to-peak height of the drawn body), and that a working mark actually throws ribbons within thirty seconds. Both were *failing* when written — rotation emphasis turned out to be swallowed by a spring. A third, that no persona-and-mood pair slides the body off its canvas, was removed with the position bound it held: the original animation is allowed to run past the viewBox.

`BotMarkRestTests` uses the production `BotMarkProgramme.forMood`. It forbids sleeping, powering-down and bored in production and allows drowsy only for sleepy, across every mood, quiet/hover condition and weekday/weekend/day/night context. Two-minute simulations require zero resting-state frames for other personas and keep sleepy's night-time idle accent under a quarter. Low-eyelid time is bounded for sleepy; happy laughter and playful dizzy spins are not classified as sleep merely for narrowing their eyes. Night boundaries, awake entry and mood priority are checked separately. These are local engine-frame checks, not real panel input. [ui/rings-and-surface.md](ui/rings-and-surface.md#animated-marks)

`BotMarkContinuityTests` drives every persona through ninety seconds of realistic switching — mood changes, pointer on/off/moving, `workFinished` and `limitReset` one-shots, from a seeded scenario — and bounds the worst single frame at 30fps to 30 units of body travel and 30° of rotation. Ordinary motion peaks near 16 and 15; before `BotMarkEngine.render` carried the difference across a change of state, interrupted celebrate turns and morph poses reached 144° and 108 units. Checked against the unfixed engine: it fails. [ui/rings-and-surface.md](ui/rings-and-surface.md#animated-marks)

`BotMarkAttentionTests` moves the pointer onto the panel and measures the largest one-frame step of each eye's centre in the face's own space over the next half second, per persona. It is the median of twenty-one runs because the engine's own glances are random and some personas' gestures dart the eyes as far as a snap would; playful's do so often enough that it is left out. Proud and eager are already in a state that spins when the first ambient gesture is due (2.5–5s), and that spin projects the eyes about as far as the snap, so their pointer arrives at one second — after the opening blink and expression have settled, and before that gesture. The other personas arrive at three seconds. Before `attention` was eased, arrival measured 30–60 units in a frame; after, 1–5 ([ui/rings-and-surface.md](ui/rings-and-surface.md)).

`BotMarkChoreographyTests` prevents personalities from collapsing to the same state sets or just a different ordering: eight distinct idle signatures, distinct sets in every mood and attention response, and distinct work-finished acknowledgements. Everyday/attention states must also be disjoint from **every** persona's work states. Frame tests forbid idle ribbons, catch a live work ribbon before switching to idle, and ensure event particles stop when playback ends even if the observed event flag stays true. It drives complete production scenes to check every beat is visited in order. The canvas bound is gone: the original animation may leave the viewBox. It also checks catalogue coverage, safe state meanings, event duration/resumption, face-vs-morph duty cycle, the bouncing ball's drawn size, and expression-pool cycling. Its optional contact sheet uses `drawBotMark` through `ImageRenderer`, not a mock renderer or a claim of real AppKit input:

```bash

```

**The animated mark is tested where it fails silently.** `BotMarkTests` covers the mood rule (busy outranks spent; no reading is unavailable), the persona rule (no character may play a state that contradicts the reading, and each wears a real, distinct shape), the colour deal (neighbouring rings never within 30° of hue, the same rail dealt the same way twice) and the contrast rule (no provider's body sinks into the disc, eyes always clear the body), plus that every state named anywhere exists in the bundled table and that the table is whole — 18 shapes of 96 points, 25 eye pairs, 39 states. The colourless rail is `Provider.allCases` filtered by `BotMarkTint.brand(for:) == nil`, not a hardcoded count — that count has already gone stale once and failed a sync for the wrong reason. Qoder stays branded. None of those crash when they break: a mark that quietly reads `idle` about a signed-out provider, or a black body on a black disc, just looks like nothing. What the animation *looks like* is a screenshot question and is not tested.

## Before the Mac build

`./Scripts/fork-compat-check.sh` runs on Linux and is the first CI step that looks at the tree. It rejects conflict markers, unbalanced braces in the files a merge rewrites, a second `async let` / `rawQoder` binding for the same provider, a `Provider` case that `UsageBatch.collect` never `load`s, and a switch on `Provider`, `UsageWindow.Kind`, `ConnectionRemedy`, `UsageRoute`, or `ProviderUsage.Unavailability` that drops a fork case (`.qoder`, Kimi's session reasons, Qoder's credit kinds, …) and has no `default`. It then runs `./Scripts/check-localization.sh`. `--fill-placeholders` copies missing ja / ko / zh-Hant keys from English as placeholders; zh-Hans is not filled. The weekday upstream-sync agent should run the script after the merge, before pushing the pull request. It does not replace `swift build` or `swift test`.

**Integrations are tested outside `swift test`.** In `Integrations/raycast`, `npm ci` then `npm test` runs `tests/report.mjs` against the TypeScript consumer and the real shell formatter (gaps, balance-only accounts, estimates, account selection, tmux escaping); `npm run build` and `npm run typecheck` check the extension. Real Raycast/sketchybar UI and macOS URL delivery need the host apps and a bundled Pulse. [integrations.md](integrations.md)

## CI compiles the tests with an older Swift

A local pass does not prove CI will compile. The `macos-26` runner's Swift is older and stricter: it would not convert a `CGFloat` into a `Double` tuple element on assignment, which local Swift 6.4 accepts, and that line in `BotMarkContinuityTests` failed the 1.4.0 release (measured then). Write `CGFloat` ↔ `Double` conversions out in tests, as the app code does.

## Conventions

**The executable target is tested directly** (`@testable import Pulse`, allowed since Swift 5.5). Pulse is one app; splitting it into two targets for the test runner would be a refactor for its own sake.

**A symbol may be `internal` instead of `private` so a test can reach it**; its comment says so and says not to tidy it back (`AntigravityUsageService.Reply`, `windows(from:)`).

**A suite that reads or writes `PanelMetrics`, or measures `DockLayout`, is nested in `PanelGlobalsSuite`** (`extension PanelGlobalsSuite { @Suite struct … }`), which is `.serialized`. `PanelMetrics` is process-wide and Swift Testing runs top-level suites in parallel, so `.serialized` on one suite alone let another change the globals mid-measurement and `FreeAcrossTests` failed intermittently. Nested there: `RailGeometryTests`, `PanelHoldTests`, `RailOffsetTests`, `FreeLyingRailProportionTests`, `NotchGeometryTests`, `PanelIntentTests`, `FreeAcrossTests`, `BottomDockTests`, `CardRoomTests`, `RailMoneyTests`.

**Nothing outside `PanelGlobalsSuite` may move the globals either, and `AppSettings.restored()` does**: it rewrites every metric, the ring budget and the language from the runner's defaults domain (`swiftpm-testing-helper`, which other tests write to) and never puts them back. A real `AppDelegate()` restores, so when `MenuBarIconSettingTests` built one, `FreeAcrossTests` failed whenever it ran after it — about one full run in several (2026-10-13). A test that needs a delegate builds `AppDelegate(settings:)` on isolated defaults.

**Resolve a SwiftUI `Color` on the main actor.** A colour backed by an `NSColor` provider (the usage colours, `Color.pulse*`) syncs onto the main thread to resolve; two tests doing it at once from the cooperative pool deadlocked the run (2026-10-09). `UsageTintTests` is `@MainActor` for this.

## Fixtures

`Tests/PulseTests/Fixtures/` is copied whole into the test bundle so a schema change diffs readably; read with `Bundle.module.url(forResource:withExtension:subdirectory:)`. Captured payloads carry no account name, email or token — check before committing. A quota reply should be bucket ids, display names, fractions and reset times, nothing more.

**A temporary fixture removes only the root it created.** Never `deletingLastPathComponent()` from a fixture path: above a file in the system temporary directory is the system temporary directory. `AgentStoreTests`' `temporary(_:)` returns the owned root, and each test defers a `removeItem` on exactly that URL.

**A throwaway defaults suite comes from `TestDefaults.make(_:)`, never `UserDefaults(suiteName:)` with a plain name.** A named suite is a plist in `~/Library/Preferences` that cfprefsd writes back even after `removePersistentDomain` and deletion (2,331 had piled up by 2026-10-09). The helper names the suite by an absolute path in its own temporary directory and removes that directory.
